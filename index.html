Bucketed by calendar month, not by day, against today (). Methodology notes

Stock figures shown throughout this tool are derived, not a separate column in the source file: the report's SELECT only exposes running/cumulative stock positions per line, so "available stock" here is read from the first line in each component's priority queue (where cumulative demand = 0), which mathematically equals the true starting stock for that (component, plant, BOM level) group.

BOM-level stock partitioning: each level's cumulative-demand window is partitioned independently by (component, plant) per level. If the same component appears both as a direct Level‑1 item and as an upstream Level‑2+ requirement feeding a different cascade, each level checks that component's full starting stock independently rather than sharing one depleting pool. This can slightly overstate availability where a component is genuinely shared across a direct-use path and a replenishment-cascade path. The Supply Simulator respects this same partitioning, so results are only directly comparable within one BOM level at a time.

Aging buckets compare calendar months, not days: a requirement date anywhere in the current month is "current month" even if that date has already passed this month.
